# CVTE D3 × π0.5 初步计划评审

评审日期：2026-11-10
结论：**方向合理，但原计划不完整，且不能直接进入实机实施。**

## 总体判断

原计划选择“外骨骼遥操作 → LeRobot 数据 → π0.5 微调 → 受控部署”的主线是合理的，安全分层、坐标标定、原始数据追溯和阶段验收意识也正确。主要问题不是目标错误，而是文档在数据章节中途结束，尚未给出训练、部署、评测、依赖锁定、环境兼容性和明确的阶段门。

此外，原计划把 D3 接口和 LeRobot 适配全部列为未知；经核对 CVTE 当前源码，已有 D3 驱动可复用，但其实现不能原样上机。

## 做得合理的部分

1. 第一阶段限定右臂、固定工位和单一药盒任务，范围适合先打通闭环。
2. 外骨骼与机器人之间设置映射/安全层，避免人体信号直接下发。
3. 强调时间戳、配置哈希、标定版本和失败 episode，利于排查数据问题。
4. 先只读、再低速小动作、再正式采集，实施顺序正确。
5. 不把未验证接口写成已实现能力，事实边界清楚。

## 必须修正的关键点

### P0：D3 不是 `CArmSingleCol` 单臂控制器

CVTE `carm-lerobot` 的 D3 实现明确使用 `carm.CArmDualBot`，每臂 7 个关节。第一阶段“只用右臂”应当是项目动作空间和安全策略，而不是把设备误建模为六轴单臂。

建议：底层保持 D3 双臂设备语义，上层增加右臂-only 投影；左臂可以只读诊断，但禁止进入策略输出和动作下发。

### P0：供应商 D3 LeRobot 驱动存在上机安全阻断项

锁定 commit `31b1349...` 中观察到：

- `D3Robot.__init__` 创建 SDK 对象后立即 `set_ready()`，并调用 `reset_to_initial_position()`；
- 复位函数会给左右臂下发硬编码关节目标，并操作左右夹爪；
- `is_connected` 只检查相机，不检查机械臂 SDK 连接；
- `disconnect` 仅把对象置空，未显式展示控制器断开/安全停止；
- 即使配置禁用左臂动作，action schema 仍包含左右臂字段；
- `move_mode="both"` 明确不支持推理。

建议：在 `src/robots/d3/` 实现安全包装或维护最小补丁，禁止构造/连接时运动，显式管理连接与停止，并让训练和推理动作空间只包含右臂。完成单元测试和现场检查前，不运行任何供应商示例的运动路径。

### P0：原计划文档未完成

原文件止于“每个 episode 的建议内容”表格第三行，缺少数据质量、训练、推理、评测、风险和里程碑，因此不能作为执行计划验收。

建议：采用本次补全后的阶段门，所有 P0 项必须有证据后才能进入下一阶段。

### P1：采集表示和模型动作语义混在一起

原计划优先“末端相对位姿增量”，而 CVTE 驱动提供 `joint`、`pose` 和 `both`；LeRobot π0.5 的“relative actions”又是模型预处理层的 `action - state`。三者不是同一个概念。

建议：

1. 先测量外骨骼输出和 D3 跟踪接口；
2. 首批调试数据可记录 joint + pose 作为诊断，但不要用 `both` 训练后直接推理；
3. 正式数据在 `joint` 与 `pose` 中选择一个固定动作契约；
4. 是否启用 π0.5 relative action 另做 A/B 验证，并保持夹爪绝对量。

### P1：采集环境与 SDK 推荐环境存在版本冲突

CVTE SDK Demo 推荐 Ubuntu 20.04/Python 3.8/ROS Noetic/Foxy，而当前 `carm-lerobot` 要求 Python >= 3.12。虽然 `carm` 声明支持 Python 3.6+，Python 3.12 与实际控制器/相机栈仍需验证。

建议：采集、LeRobot 训练、OpenPI 分环境；先在服务机冻结一份可复现版本清单和只读连接测试结果。

### P1：缺少可度量的成功定义

“完成抓取和放置”不足以指导采集和模型选择。

建议在实机基线后冻结：抓取/放置成功判定、目标区容差、物体掉落/碰撞/超时定义、每个场景重复次数、端到端延迟上限、数据丢帧阈值和策略安全中止率。

### P1：数据划分必须防止泄漏

相邻 episode、同一会话和同一场景高度相关，按帧或随机 episode 切分会高估性能。

建议按 session + 场景/物体组合切分，保留独立真机测试场景，并在数据清单中记录分组原因。

## 推荐的执行阶段门

| 阶段 | 主要输出 | 进入下一阶段的条件 |
| --- | --- | --- |
| G0 需求冻结 | D3/外骨骼/相机/夹爪清单，任务成功定义 | 设备型号、SDK、控制器固件和安全责任人明确 |
| G1 软件基线 | 锁定依赖、分环境安装、只读自检 | SDK 状态读取稳定，版本可复现，无运动副作用 |
| G2 安全与映射 | 右臂-only 包装、急停、限位、标定 | 左臂零命令；断连/超时必停；低速小动作通过 |
| G3 试采集 | 10 个诊断 episode、质量报告 | schema、延迟、帧率、单位、动作范围和回放通过 |
| G4 数据采集 | 版本化 LeRobot 数据集 | 成功/失败标签完整，切分无泄漏，质量门通过 |
| G5 π0.5 微调 | 训练配置、checkpoint、离线报告 | 固定验证集指标和动作安全检查通过 |
| G6 受控部署 | 策略客户端、安全网关、真机报告 | 单次低速评测通过后才逐步扩大场景 |

## 框架选择建议

第一条闭环优先用锁定的 `carm-lerobot`：它同时包含 D3 驱动、LeRobot 记录器和 π0.5 policy，集成工作量最低。但 D3 驱动必须先加安全包装。

OpenPI 保留为第二条对照路径：当需要使用其原生 checkpoint、训练配置或独立策略服务器时，再从同一个冻结的 LeRobot 数据集接入。不要在第一批数据还未验证时同时维护两套训练栈。

## 本机已有文件的处理结论

- 工作区现有约 35 GiB 数据是 GR3/OAK-D-W/Fourier Hand 数据，不是 D3 数据，不能直接作为本任务训练集。
- 数据元信息含机器标识、内网地址和运行环境信息，原始文件不应进入公开 Git 仓库。
- 工作区根目录存在明文密码文件，已明确排除，不复制、不提交。
- 本次只提交项目文档、无密钥模板、依赖锁和目录骨架；原始数据、模型、日志和第三方源码均保持在 Git 外。
