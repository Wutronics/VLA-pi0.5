# D3 药盒任务数据集约定（待实机冻结）

## 数据边界

一个 episode 表示一次完整尝试：复位完成后开始，覆盖接近、抓取、搬运、放置和退出，并以成功、失败或人工中止结束。失败和中止数据保留在原始层，但是否进入训练集由清洗规则决定。

## 最小字段

| 类别 | 必需内容 |
| --- | --- |
| 任务 | 稳定的英文任务提示、任务版本、对象/起点/终点场景 ID、结果标签 |
| 观测 | 至少一台场景 RGB 相机；建议增加右腕 RGB，相机名称在采集、训练、推理中完全一致 |
| 状态 | 右臂 7 关节状态、右夹爪状态；顺序、单位和来源写入 schema |
| 动作 | 右臂 7 维目标与夹爪命令；明确是绝对/相对、关节/末端和时间语义 |
| 时间 | 来源时间、主机接收时间、帧序号；统计延迟、抖动、丢帧和陈旧数据 |
| 追溯 | SDK/驱动 commit、控制器固件、配置哈希、`calibration_id`、操作者匿名 ID、会话 ID |

左臂状态可以作为诊断原始字段记录，但第一阶段不能进入策略动作空间，也不能由策略输出驱动。

## 数据分层

- `data/raw/`：不可变原始记录；保留外骨骼原始流和 D3/相机反馈。
- `data/processed/`：可复现转换得到的 LeRobot 数据集。
- `data/samples/`：脱敏的小型契约样例，仅用于测试代码。

每个 processed 版本应保存：原始 episode 清单及哈希、转换代码 commit、转换配置、过滤原因、特征 schema、归一化统计和质量报告。

## 切分规则

不能按帧随机切分。训练/验证/测试至少按采集会话切分；若评估场景泛化，则还应按药盒外观、起点或目标区域分组，防止相邻轨迹泄漏。

## 质量门槛

正式训练前，自动检查：

- episode 文件完整且结果标签有效；
- 时间戳单调，观测/动作延迟和丢帧率在实测阈值内；
- 图像无长时间黑帧、冻结或曝光突变；
- 动作维度、字段顺序、单位和范围一致；
- 无 NaN/Inf，无无法解释的跳变或限位外动作；
- 相机名称、分辨率和颜色通道在采集与推理配置中一致；
- 每个 episode 都能追溯到配置和标定版本。

阈值不得在没有实测数据时拍脑袋填写。先用 10 个 dry-run/低速 episode 建立延迟和噪声基线，再冻结数值。

## 与本机现有数据的关系

本机工作区中的约 35 GiB 数据来自 GR3、OAK-D-W 和 Fourier Hand，不是 D3 数据。其机器人、动作维度、相机、任务描述和采集栈均不同，因此不能直接作为本实验 π0.5 训练集。可在单独授权和脱敏后仅参考其记录组织方式；本仓库没有上传这些原始文件。
